# Copipe

ホットキーを**押している間だけ**、マウスカーソルのそばに小窓を出して**クリップボードの履歴**を表示する、
Windows 11 向けの常駐ツール。**管理者権限もインストールも不要**。

最終的には「履歴の項目をダブルクリックやドラッグ＆ドロップで他のアプリに入力できる」ようにすることを
目指して、機能を 1 ステップずつ足している。
現在は **ステップ 3 (ダブルクリックでテキストカーソルの位置に入力)** まで。

対象環境: Windows 11 25H2 / build 26200 で開発・検証。

## ビルドと起動

```powershell
.\build.ps1          # ビルド (起動中の Copipe があれば先に正常終了させる)
.\build.ps1 -Run     # ビルドして起動
```

生成物は `bin\Copipe.exe`。単一ファイルでダブルクリック起動できる。

Windows 標準の `csc.exe` (.NET Framework 4.8) だけでビルドするため、
.NET SDK も Visual Studio も要らない。

## 使い方

1. `Copipe.exe` を起動すると、タスクトレイにアイコンが出る。以後、コピーした文字が履歴に貯まる
2. **ホットキー (既定は F1) を押し続ける**か、**設定した修飾キー (Ctrl など) を 2 回押す (ダブルタップ)** と、
   マウスカーソルの右下に小窓が出て、履歴が新しい順に並ぶ。ホットキーは離すと消え、
   ダブルタップで出した小窓は**出したまま**になり、項目を入力すると閉じる (ほかの閉じ方は下記)
3. 押したまま、**入力したい項目をダブルクリック** (設定でシングルクリックにもできる) するか、
   **項目の番号の数字キーを押す**と、入力中のアプリの**テキストカーソルの位置**に全文
   (改行・タブを含む) が入力される。押したままなら、続けて別の項目も入力できる
4. **ホットキーを離す**と小窓が消える

小窓の上には見出しが出る。左が今のモード (クリップボード履歴 / 定型文)、右がモードキーでの切り替え先
(例: `Tab: 定型文`)。

小窓は入力中のアプリからフォーカスを奪わないので、小窓をクリックしてもテキストカーソルは
元の位置に残っている。

数字キーで選ぶ:

- 一覧の先頭 10 件に、キーボードの並びどおり **1〜9、0** の番号が付く (10 件目が 0)。
  11 件目以降は番号が無く、数字キーでは選べない (クリックで選ぶ)
- 上段の数字キーもテンキーも使える (テンキーは NumLock がオンのとき)
- 押した数字は、小窓を出している間だけ Copipe が受け取るので、入力中のアプリには入らない。
  ホットキーを離せば、数字キーは普通に使える
- 選んだ項目は一覧で強調表示される。項目が無い番号 (履歴が 3 件のときの 7 など) は何もしない
- 数字キーを素早く続けて押しても、押した順に 1 件ずつ入力される (1 件あたり約 0.25 秒)

ピン止め (履歴モードで**行を右クリック**):

- 右クリックのメニューの「ピン止め」で、その項目を**一覧の上部に固定**する。新しくコピーしても押し流されない。
  新しくピン止めしたものがピン止めの一番上に入る
- ピン止めした行は**番号なし**で、右端に 📌 が付く。数字キーの 1 は、ピン止めの下にある普通の履歴の 1 件目。
  ピン止めと普通の履歴の間には区切り線が入る
- **📌 をクリックするとピン止めを外す** (「貼り付けの操作」の設定によらず 1 回のクリック。入力はしない)。
  右クリックのメニューの「ピン止めを外す」でもよい。外した項目は普通の履歴の一番上に戻る
- ピン止めした行の本文部分は、普通の履歴と同じくクリック (ダブルクリック) で入力できる
- ピン止めは**10 件に数えず**、トレイの「履歴を消去」でも**消えない**。ピン止めした内容をまたコピーしても増えない
- ピン止めは history.json の `Pinned` に保存され、Copipe を終了しても残る

項目から入力すると:

- クリップボードの中身は、**入力した内容に置き換わる** (そのまま Ctrl+V でもう一度貼れる)
- 入力した項目は**履歴の先頭に移動しない**。入力中に一覧の並びが変わらないので、
  続けて別の項目を選んでも番号や位置がずれない。Copipe を起動し直しても先頭には戻らない
- 「貼り付けの操作」をシングルクリックにしているときに、うっかりダブルクリックしても、入力は 1 回だけ

定型文モード:

- ホットキーを押したまま**モードキー (既定は Tab) を押す**と、小窓の中身が「クリップボード履歴」と
  「定型文」で切り替わる。もう一度押すと戻る。小窓は出したまま
- **小窓の上でマウスのホイールを回しても切り替わる**。↓ に回すと定型文、↑ に回すと履歴。端で止まる (回り込まない)。
  そのため、一覧のホイールでのスクロールはしない (15 件を超えたらスクロールバーで動かす)。
  Windows の設定「非アクティブ ウィンドウをホバーしたときにスクロールする」(既定でオン) がオフだと、
  ホイールは小窓ではなく入力中のアプリに届く
- 小窓を開くときは**いつもクリップボード履歴**から。定型文モードに入るときは**いつも一番上の階層**から
- 定型文は**グループ**と**定型文**の 2 種類。グループの中にもグループと定型文を置ける (深さの制限なし)
- どの階層も **1〜9、0 の 10 個の枠**が決まっていて、いつも 10 行出る。空いている枠は「（空き）」
- 番号の数字キーかクリック (「貼り付けの操作」の設定どおり、ダブルかシングル) で選ぶ。
  **定型文なら入力**し、**グループなら中に入る**。空きは何もしない
- **Esc で 1 つ上の階層に戻る**。一番上で押しても何もしない
- **見出しの階層名 (パンくずリスト) をクリックすると、その階層へ移る** (例: `定型文 > 社外 > 挨拶` の「定型文」で一番上へ)。
  シングルクリックで移る。今いる階層 (右端) のクリックでは何もしない。移れる階層名の上ではカーソルが指の形になる
- 見出しに今いる階層が出る (例: `定型文 > 社外 > 挨拶`)。グループは `📁` (フォルダの絵文字) 付きで出る。小窓の描き方 (GDI) では絵文字はカラーにならず、白黒の線画になる
- 一覧に出す名前は、定型文は表示名 (無ければ本文の最初の空でない行)、グループは名前。入力するのは本文の全文
- モードキーと Esc も数字キーと同じく、小窓を出している間だけ Copipe が受け取る
  (Esc は定型文モードの間だけ)。ホットキーを離せば普通に使える

定型文の登録・編集・削除 (定型文モードで**行を右クリック**):

| 右クリックした枠 | メニュー |
|---|---|
| 空き | 定型文を登録... / グループを作成... |
| 定型文 | 履歴にピン止め / (区切り線) / 編集... / 削除 |
| グループ | 名前を変更... / 削除 |

- ホットキーを押したまま右クリックして、メニューから選ぶ。選ぶ前にホットキーを離すとメニューも閉じる
- 「履歴にピン止め」は、その定型文の本文をクリップボード履歴のピン止めの一番上に入れる (ダイアログは出ず、小窓もそのまま)。
  既に履歴やピン止めにある内容なら、そこから一番上に移る。グループには出ない
- 登録・編集・グループの操作を選ぶとダイアログが出る。**ダイアログを出したら、ホットキーは離してよい**。小窓は閉じ、数字キーや Tab も
  普通に打てる。閉じると、元のアプリが前面に戻る
- 定型文のダイアログは「表示名 (省略可)」と「本文」。本文の欄では Enter で改行、**Ctrl+Enter で確定**、Esc で取り消し。
  本文が空 (空白だけも含む) の間は OK を押せない
- グループのダイアログは名前だけ。空の間は OK を押せない
- 削除は確認してから (取り消せない)。グループは中の定型文とグループの件数も出す。「いいえ」が既定のボタン
- 変更はすぐ `phrases.json` に保存され、次に小窓を出したときから使える

定型文の並べ替え (定型文モードで**行をドラッグ＆ドロップ**):

| 落とす先 | 動き |
|---|---|
| 定型文・空きの行、グループの行の上下の端 | 入れ替える (空きなら移す) |
| グループの行の中央 | そのグループの最初の空きに入れる |
| 見出しの階層名 (例: `定型文 > 社外` の「定型文」) | その階層の最初の空きに出す |

- ドラッグしたまま、グループの行の中央か見出しの階層名で**約 1 秒止めると、そこが開く**。
  そのまま中の好きな枠に落とせる (深い階層へ一度に移せる)
- 入れ替える先は薄い青、グループに入れる先は枠、階層名は背景の色で示す。落とせない先ではカーソルが「禁止」になる
  (自分自身、自分の中のグループ、空きの無いグループ、入れ子が輪になる入れ替え)
- **Esc** か、ホットキーを離すとドラッグを取り消す。空きの枠はドラッグできない
- 並べ替えはすぐ `phrases.json` に保存される。ドラッグしても入力はしない

履歴の並べ替え (履歴モードで**行をドラッグ＆ドロップ**):

- 行をつかんで別の行に落とすと、**その行の位置に移る** (間の行は 1 つずつずれる)
- **ピン止めはピン止めの中、普通の履歴は普通の履歴の中だけ**で並べ替えられる。反対側の行の上では「禁止」のカーソルになる
- 普通の履歴の番号 (1〜9、0) は新しい並びで振り直される。その後にコピーしたものは、今までどおり普通の履歴の先頭に入る
- 並べ替えはすぐ `history.json` に保存される。ドラッグしても入力はしない。Esc かホットキーを離すと取り消す

定型文は `%LOCALAPPDATA%\Copipe\phrases.json` に保存する。メモ帳で直接書き換えてもよい。
**書き換えると、次に定型文モードに入ったときに読み直す** (再起動は不要)。

```json
{
  "Slots": [
    {
      "Kind": "Group",
      "Name": "社外",
      "Slots": [
        { "Kind": "Phrase", "Title": "冒頭", "Text": "いつもお世話になっております。\r\n○○の△△です。" }
      ]
    },
    { "Kind": "Phrase", "Text": "取り急ぎご連絡まで。" },
    null,
    { "Kind": "Phrase", "Text": "4 番目の枠" }
  ]
}
```

- `Slots` の並びが枠の 1, 2, … , 0 番目。`null` は空き。10 個に足りなければ残りは空き、11 個目以降は読み捨てる
- `Kind` は `Group` (名前は `Name`) か `Phrase` (表示名 `Title` は省略可、本文 `Text` は必須)。
  改行は `\r\n`。読めない項目は空きとして扱い、ファイルが壊れていても起動は止めない
- BOM 付きでも無しでも読める

トレイアイコンの右クリックメニュー:

| 項目 | 内容 |
|---|---|
| 設定... (ホットキー: F1) | ホットキー・ダブルタップ・モードキー・貼り付けの操作を変える |
| 履歴を消去 | 履歴をすべて消す (確認あり)。ピン止めした項目は残る |
| 終了 | Copipe を終了する |

### 履歴

- 残すのは**テキストだけ**。画像やファイルをコピーしても履歴には入らない
- 同じ内容を続けてコピーしても増えない。前にコピーした内容をまたコピーすると、先頭へ移動する
- 残すのは**新しい 10 件まで** (番号 1〜9、0 と同じ数。定型文の 1 階層の枠数とも同じ)。超えたら古いものから捨てる。
  件数は変えられない。ピン止めした項目は 10 件に数えない
- **1 件あたり 10 万文字を超えるコピーは履歴に入れない** (Excel の広範囲コピーのたびに数 MB を
  ディスクへ書かないようにするため)
- 一覧は 1 件 1 行。改行とタブは空白に置き換え、長い文は「…」で省略する。
  履歴には全文が入っている (将来の再コピーやドラッグ＆ドロップで全文を使う)
- 履歴は `%LOCALAPPDATA%\Copipe\history.json` に保存され、**Copipe を終了しても残る**

> **注意**: コピーした文字はそのままディスクに残る。パスワードなどをコピーした場合は、
> トレイメニューの「履歴を消去」で消すこと。

### 設定

トレイアイコンを右クリック →「設定...」。

**初めて起動したとき** (設定ファイルがまだ無いとき) は、最初に設定画面が出る。OK でもキャンセルでも、
閉じると設定ファイルができ (キャンセルなら既定の設定)、次からは出ない。

- **ホットキー**: 欄を選んで、押し続けたいキーを押す (F1・Pause・無変換など)。**Ctrl・Shift・Alt・Windows キーとの組み合わせは使えない**。
  Ctrl などを押したままキーを押しても、キーだけを取り込む。修飾キーを押したままだと、小窓で使う Tab が Alt+Tab に
  なるなど Windows と取り合いになり、Windows が使っている組み合わせ (Win+Space など) は設定画面に届きもしないため
- **モードキー**: 欄を選んで、キーを押す。ホットキーと同じ決まり (修飾キーは付けない)。ホットキーと同じキーは指定できない
- **ダブルタップ**: 欄を選んで Ctrl・Shift・Alt のどれかを押す。**そのキーを 2 回押すと小窓が出て、出したままになる**。
  **項目を入力すると閉じる**。ほかに**もう一度ダブルタップ・Esc・小窓の外のクリック・別のアプリへの切り替え**で閉じる (定型文モードで階層の中にいるときの
  Esc は 1 つ上に戻る。一番上で押すと閉じる)。出している間は数字キー・Tab・Esc を Copipe が受け取る。
  ホットキーと並行して使える。Alt は、アプリによっては押して離すとメニューバーに
  フォーカスが移るので、選ぶと注意が出る
- **「なし」ボタン**: ホットキー・ダブルタップの欄の右にある。押すとその起動方法を使わない (欄に「（なし）」と出る)。
  **両方「なし」にはできない** (OK を押せない)
- **貼り付けの操作**: ダブルクリック (既定) か シングルクリック。定型文のグループに入る操作も同じ。ダブルクリックのときは、
  シングルクリックでは何も起きない (項目を確かめるだけのクリックで誤って入力しない)
- **Enter か OK** で確定、**Esc** で取り消す。変更はその場で反映される (再起動は不要)

ホットキーが既に使われている場合は「他のアプリまたは Windows が使用中のため設定できませんでした」と
表示して、**設定画面に戻る**。どのアプリが使っているかは Windows が教えてくれない
(ホットキーの所有者を調べる API が無い) ため、表示できない。

**F12 は Windows がデバッガー用に予約している**ため、どのマシンでも使えない
([RegisterHotKey のドキュメント](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-registerhotkey))。

指定できないキーもある。設定画面で押すと理由が出て、確定できない。

| キー | 理由 |
|---|---|
| **半角/全角、英数、カタカナ ひらがな** | 押して離しても「押されたまま」に見えるため、離したことを判定できない (実測。下記) |
| Ctrl、Shift、Alt、Windows キーとの組み合わせ | 修飾キーを押したままだと、小窓で使う Tab・数字キーが Windows の操作 (Alt+Tab・Win+数字など) と取り合いになるため |
| Ctrl、Shift、Alt、Windows キーだけ | Windows がホットキーとして登録できない (押しても何も起きない) |
| Enter | 全アプリで Enter が奪われ、文字入力ができなくなる (設定画面では「確定」に使う) |
| 数字キー (上段・テンキー) | 小窓を出している間は、一覧から選ぶために使うため |

モードキーも、上の表のキーは指定できない。

前の版で修飾キー付きのホットキー (Ctrl+Space・Alt+A など) を設定していた場合は、起動時に既定の F1 に戻る
(修飾キーだけ外すと、そのキー (Space・A など) が全アプリで打てなくなるため)。

設定は `%LOCALAPPDATA%\Copipe\settings.ini` に保存される。メモ帳でも直せる。

```ini
# Copipe の設定 (メモ帳で編集できます)
# Hotkey: 押している間だけ小窓を出すキー。修飾キー (Ctrl など) は付けられない。使わないときは None。例: F1、Pause、IMENonconvert (無変換)
Hotkey=F1
# DoubleTap: 2 回押して、2 回目を押し続けている間だけ小窓を出す修飾キー。Ctrl・Shift・Alt か None (使わない)
DoubleTap=None
# InsertClick: 履歴の項目を貼り付ける操作。Double (ダブルクリック) か Single (シングルクリック)
InsertClick=Double
# ModeKey: 小窓を出している間に押して、クリップボード履歴と定型文を切り替えるキー。例: Tab、F2
ModeKey=Tab
```

読めない値が書かれていた場合は、既定 (F1・ダブルタップなし・10 件・ダブルクリック・Tab) に戻して起動する。
Hotkey=None と DoubleTap=None の両方が書かれていたら、小窓を出せなくならないようホットキーを F1 に戻す。

## 注意点

- ダブルタップの 2 回目を押し続けたまま Tab・Esc を押すと、Alt+Tab・Ctrl+Esc などとして Windows が受け取ることがある。
  指を離してから押せばよい
- **Copipe の起動中は、設定したホットキーが他のアプリに届かない**。既定の F1 のままなら、
  VS Code のコマンドパレット (F1) なども開かなくなる (Ctrl+Shift+P は使える)。
  Ctrl+F1 などの修飾キーとの組み合わせは、他のアプリに普通に届く
- **ホットキーを押しても小窓が出ないときは、別のアプリがそのキーを横取りしている可能性がある**。
  このマシンでは一時期、F1 だけが別のアプリの低レベルキーボードフックに横取りされ、
  Copipe の登録自体は成功しているのにキー入力が届かなかった (実測。F2〜F11・Pause などは届いた)。
  その場合は設定で別のキーに変える
- **管理者として実行中のウインドウ (昇格したターミナルやレジストリエディターなど) が前面にあると、
  ホットキーを押し続けても小窓は一瞬で消える**。UIPI により、`GetAsyncKeyState` が
  「前面のスレッドにアクセスできない」ときも 0 (＝離されている) を返すため
  ([Microsoft Learn](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-getasynckeystate))。
  E2E では昇格したウインドウを用意できないので未検証 (UAC の同意が要る)。
  なお、このマシンのユーザーは Administrators グループに属していないため、
  タスクマネージャーなどが自動で昇格することは無い
- **ダブルクリックでの入力は、管理者として実行中のアプリには届かない** (UIPI により、送った Ctrl+V が
  届かない)。入力できなかったときは音で知らせる
- Copipe を二重に起動すると、2 つ目は「ホットキー F1 を登録できませんでした」と表示して終了する
  (キー名は設定したもの)。他のアプリがそのキーを使っている場合も同じ表示になる
- Excel で巨大な範囲をコピーした直後は、Excel がテキストを作り終えるまで表示が遅れることがある

## 実測値

このマシンで `tools\verify.ps1` を実行して計測した値。

| 項目 | 値 | 計測した場所 |
|---|---|---|
| ホットキーを押してから小窓が出るまで | 2〜18 ms (起動後の初回が最も遅い) | E2E (キーは擬似入力) |
| ホットキーを離してから小窓が消えるまで | 14〜32 ms (離したことを約 30 ms 間隔で調べている) | E2E |
| 常駐中のメモリ | ワーキングセット 約 39 MB / プライベート 約 25 MB | E2E |
| ダブルクリックしてから入力されるまで | 約 160〜180 ms (うち 100 ms は履歴ツールが読み終えるのを待つ時間) | E2E |
| 数字キーを 3 つ続けて押して、全部入力されるまで | 約 0.8 秒 (1 件ずつ順に入力。1 件あたり約 0.25 秒) | E2E |
| 500 万文字のテキストの読み取り | 約 10〜20 ms | 検証 5 (`ClipboardReader.Read` を直接呼ぶ) |
| ファイル 1 万件の読み取り | 約 3 ms (DragQueryFile で 1 件ずつ取り出す方式では約 2〜3 秒だった) | 検証 5 |

表示・非表示までの時間は、ハーネスが空回りで待って計った値 (Sleep の刻み約 15.6 ms に丸めていない)。

## 設計上の要点

### ダブルタップ: Raw Input で読むだけ

- 修飾キー (Ctrl・Shift・Alt) 単独はホットキーとして登録できないので、`RegisterRawInputDevices` (`RIDEV_INPUTSINK`) で
  キーの押す・離すを受け取って判定する。**読むだけ**で、キー入力を横取りも遅延もさせない (キーボードフックは使わない)。
  ダブルタップを設定しているときだけ登録し、設定画面を開いている間は止める
- ダブルタップで出した小窓は、出したままにする。フォーカスを奪わない小窓なので「外がクリックされた」という知らせが
  届かない。出している間だけ、マウスのボタンを押した瞬間を Raw Input (`MouseClickWatcher`、読むだけ) で受け取り、
  小窓の外で押されたら閉じる。一定間隔で `GetAsyncKeyState` を見る方法では、押してすぐ離すクリック
  (タッチパッドのタップなど) を見落とした (E2E で実測)。前面のウインドウは 50 ms ごとに調べ、入力先から
  別のウインドウに変わったら閉じる
- 判定 (`DoubleTapTracker`): 1 回目を 300 ms 以内に離し、離してから 400 ms 以内に 2 回目を押すと成立。
  間に別のキーが押されたら取り消す (Ctrl+C を 2 回などを取り違えない)。左右の Ctrl などは同じキーとして扱う。
  押し続けたときの押下の繰り返しは 1 回として数える
- 2 回目を押し続けている間は、数字キー・Tab・Esc が Ctrl+1 などとして届くので、そのキー付きでも登録する
- ホットキーとダブルタップのどちらかで小窓を出している間は、もう一方は無視する (ダブルタップで出したときは、
  もう一度のダブルタップで閉じる)

### ホットキー: RegisterHotKey + 離したことだけポーリング

- 押した瞬間は `RegisterHotKey` (`MOD_NOREPEAT` 付き) の `WM_HOTKEY` で受け取る。
  押し続けても通知は 1 回だけ
- 離した瞬間は、**小窓を出している間だけ** 30 ms ごとに `GetAsyncKeyState` で調べる
- キーボードフック (`SetWindowsHookEx`) は使わない。全キー入力を監視しないので、
  セキュリティソフトにキーロガーと疑われにくい
- `RegisterHotKey` が横取りしたキーでも、`GetAsyncKeyState` にはキーの状態が反映されることを
  E2E で確認している (ただし前面が管理者として実行中のウインドウのときは例外。「注意点」を参照)

### 履歴: クリップボードの変化の通知で貯める

- `AddClipboardFormatListener` で `WM_CLIPBOARDUPDATE` を受け、その都度読む。
  ポーリングではないので、待っている間の負荷はほぼ無い
- 通知のときに読めなかった場合の保険として、**起動時**と**ホットキーを押した時**にも今の内容を拾う。
  この拾い直しでは、**すでに履歴にある内容の並びは変えない** (本当のコピーのときだけ先頭へ移動する)。
  自分の書き込みはクリップボードの持ち主が小窓かで見分けているが、Copipe を起動し直すと小窓も
  作り直されるため、前回貼り付けに使った内容を自分の書き込みと見分けられない。拾い直しで並びを変えると、
  それが起動のたびに先頭へ戻ってきてしまう (E2E で見つけた不具合)
- シングルクリック・ダブルクリックの判定には、ListBox の `MouseClick` (1 回目のクリック) と
  `MouseDoubleClick` (2 回目) を使い、設定に応じてどちらか一方だけで入力する。
  ダブルクリックの 2 回目では `MouseClick` が出ないので、シングルクリックの設定でダブルクリックしても 1 回だけ
- 保存は JSON (`DataContractJsonSerializer`)。改行やタブを含む文字もそのまま扱える。
  書き込みは一時ファイルに書いてから `File.Replace` で置き換え、途中で電源が切れても壊れないようにしている
- 一覧は `ListBox` (自前描画)。将来のダブルクリック・ドラッグ＆ドロップで「どの項目か」を判定できるようにするため。
  クリックは `MA_NOACTIVATE` でフォーカスを奪わずに一覧へ届く
- `NativeWindow` (ホットキー・クリップボードの通知を受ける見えないウインドウ) の既定の動作は、
  ウインドウプロシージャ内の例外を**握りつぶす**。そのままだと「押しても何も起きない」だけで原因が
  分からないので、`OnThreadException` でアプリの例外ハンドラーに渡している

### 数字キー・モードキー: 小窓を出している間だけホットキーにする

- 小窓はフォーカスを奪わないので、そのままでは押した数字は入力中のアプリに入ってしまう。
  そこで、小窓を出している間だけ、上段とテンキーの数字キー 20 個とモードキーを `RegisterHotKey` で登録して受け取る。
  キーボードフックは使わない。矢印キーや Enter は受け取らないので、小窓を出している間も入力中のアプリに届く
- **登録はホットキーを押した瞬間の一番最初 (小窓を出す前) に行う**。小窓を出してから登録していたときは、
  表示の直後に押した数字が入力中のアプリに漏れた (E2E で見つけた)
- **ホットキーを離したら真っ先に解除する**。解除し忘れると、どのアプリでも数字や Tab が打てなくなるため。
  設定画面を開くとき・終了時にも解除する。Copipe が落ちた場合は、ウインドウが消えるときに Windows が解除する。
  E2E で「小窓を消した後は数字キーと Tab が普通に入力できる」ことを確かめている
- モードキーがホットキーと同じキーだと区別できないので、そのときはモードキーを登録しない
  (設定画面では確定できない。設定ファイルを手で書き換えた場合の保険)
- 番号で選ぶのは「今表示している一覧」の何番目か。表示中に新しいコピーで一覧が変わっても、
  見えている番号どおりの項目が入る
- 続けて入力を頼まれたときは、順番待ちにして 1 件ずつ入力する。Ctrl+V を送った後、貼り付け先が
  クリップボードを読み終えるまで 200 ms 待ってから次の項目を置く (すぐ置き換えると、前の項目の代わりに
  次の項目が貼られてしまう)。素早く 2 件クリックしたときも同じ

### クリックでの入力: クリップボードに置いて Ctrl+V を送る

- CopyQ・Clibor と同じ方式。項目の全文をクリップボードに置き、前面のアプリに Ctrl+V を送る
- 1 文字ずつ送る方式 (`SendInput` の Unicode 入力) は使わない。改行が Enter として届いてチャットが
  送信されてしまう、タブでセルが移動する、長文が遅い、といった問題があるため
- 置いた直後は CopyQ などが読みに来てクリップボードを開く (実測)。その間に Ctrl+V を送ると、
  貼り付け先のアプリが読めずに失敗することがあるので、100 ms 待ってから、クリップボードが空くのを
  確かめて (最大 1 秒) 送る。待つ間も UI は止めない (タイマーで待つ)
- Ctrl+V は `SendInput` で 4 つの入力をまとめて送る。まとめて送った入力の間には、
  利用者の入力 (押し続けているホットキーやマウス操作) が割り込まない
- **自分で置いた内容を履歴に加えない**: クリップボードの持ち主 (`GetClipboardOwner`) が
  Copipe の小窓なら、自分の書き込みとみなして無視する。持ち主は最後に `EmptyClipboard` した
  ウインドウなので、他のアプリがコピーし直せば持ち主が変わり、そちらは普通に履歴に入る

### クリップボード: Win32 API を直接使う

- WinForms の `Clipboard` クラスは、他のアプリがクリップボードを開いていると
  100 ms 間隔で 10 回リトライし、最大約 1 秒固まる。小窓をすぐ出したいので使わない
- `OpenClipboard` は 10 ms 間隔で 5 回まで試す。このマシンではコピー直後の約 200 ms の間、
  CopyQ・Clibor・エクスプローラーが断続的にクリップボードを開いていて、こちらが開けない瞬間があった (実測)。
  表示を待たせないよう、ホットキーを押した時の読み取りは短くあきらめて今ある履歴を出し、
  押している間は 100 ms ごとに読み直して、読めたら一覧の先頭に加える
- **`OpenClipboard` には必ず自分のウインドウを渡す**。実測した組み合わせは次のとおり。

  | 相手の開き方 | こちらが NULL で開く | こちらがウインドウを指定して開く |
  |---|---|---|
  | NULL で開いている | **開けてしまう** | 開けない (err=5) |
  | ウインドウを指定して開いている | 開けない (err=5) | 開けない (err=5) |

  NULL だと、NULL で開いた相手が空にしている途中の状態を読むおそれがある。
  `ClipboardReader.Read` は `IntPtr.Zero` を渡されると `ArgumentException` にしている
- 「テキストがある」と報告されたのに読めない (遅延レンダリングの持ち主が描画しない) ときは、
  読み取れなかったものとして扱う
- WinForms の `Clipboard.Clear()` は空の `DataObject` を置くので、その後には OLE の管理用の形式
  (`DataObject` と `Ole Private Data`) だけが残る (実測)。中身は無いので「空」と判定する
- ファイル一覧 (`CF_HDROP`) は、`DragQueryFile` で 1 件ずつ取り出すと件数の 2 乗の時間がかかる
  (`DragQueryFile(i)` は毎回先頭から読み飛ばす。実測で 5,000 件 0.7 秒、1 万件 3 秒、2 万件 11 秒)。
  `DROPFILES` の名前の並びを 1 回だけ走査して取り出している (Unicode 版・ANSI 版の両方)。
  現在の履歴はテキストだけだが、将来ファイルを扱うときのために残している

### 設定画面の仕組み

- 設定画面を出している間は、今のホットキーの登録を解除する。解除しないと、今のキーを押しても
  Windows がホットキーとして横取りしてしまい、画面に取り込めない
- 押されたキーは `ProcessCmdKey` で拾う。`KeyDown` だけでは F1・Tab・Alt などが拾えないため。
  キーを取り込むのはホットキー・ダブルタップ・モードキーの欄にいる間だけ。
  IME にキーを取られないよう、画面の `ImeMode` は `Disable` にしている (無変換キーを拾うため)
- 新しいキーの登録に失敗したら、その旨を知らせて設定画面に戻る
- Enter は「確定」に使い、ホットキーには指定できない。全アプリで Enter が奪われると
  文字入力ができなくなるため。Ctrl や Shift だけの指定も、Windows が登録できないので弾く
- **日本語入力の切り替えキーは使えない**。スキャンコードを送って実測した結果は次のとおりで、
  押して離した後も `GetAsyncKeyState` が「押されたまま」を返し続ける
  (次に押したときに切り替わる作りのため)。これを許すと、小窓が出たまま消えなくなる

  | キー | 仮想キー | 押している間 | 離した後 |
  |---|---|---|---|
  | 半角/全角 | 0xF3 (IME オフ時) / 0xF4 (オン時) | 押下 | **押下のまま** |
  | 英数 | 0xF0 | 押下 | **押下のまま** |
  | カタカナ ひらがな | 0xF2 | 押下 | **押下のまま** |
  | 無変換 / 変換 / NumLock / ScrollLock / F キー | 0x1D / 0x1C ほか | 押下 | 正しく解除 |

- これらのキーは .NET の `Keys` に名前が無く、`KeysConverter` が空文字列を返す。
  そのままだと画面に何も表示されず、設定ファイルにも `Hotkey=` と書かれて次回起動時に
  既定へ戻ってしまう。名前が無いキーは「半角/全角」などの日本語名で表示し、
  保存は `VK243` のような番号の形式にして読み戻せるようにしている

### 定型文の右クリックメニューとダイアログ: 前面の扱い

- 右クリックのメニューは **Windows 標準のポップアップメニュー** (`TrackPopupMenuEx`、選ぶまで戻らない) で出す。
  WinForms の `ContextMenuStrip` は、フォーカスを奪わない小窓から出してコードで閉じると、
  2 回目以降の表示が 1.5 秒以上遅れた (E2E で実測)
- 標準のメニューを出すと、持ち主の**小窓が前面になる** (実測)。そのままだと、選ばずに閉じた後に
  数字キーで選んだ定型文が元のアプリに入らない。そこで、**ホットキーを押した時点で前面だったアプリを覚えておき**、
  メニューを閉じた後・ダイアログを閉じた後に、そこへ前面を戻す
- ダイアログと確認メッセージは、画面外にある 1×1 の**見えない持ち主** (`DialogOwner`) を付けて出す。
  持ち主が無いと、閉じた瞬間に Windows が別のアプリ (実測では VS Code) を前面にしてしまい、
  Copipe からは前面を戻せなくなる (前面を変えられるのは、前面のアプリだけのため)。
  持ち主があれば閉じた直後は持ち主が前面なので、そこから元のアプリへ戻せる
- ダイアログを出すときは、小窓を閉じ、数字キー・モードキー・Esc の横取りを解除する
  (ダイアログで数字や Tab を打てるように)。ダイアログを出している間はホットキーを押しても小窓を出さない
- メニューを出している間は、数字キーとモードキーを無視する (選ぼうとしている枠が動かないように)。
  Esc はメニューを閉じるだけ
- E2E では、メニューの項目を **MSAA (oleacc)** で読んでクリックする。UI オートメーションからは
  メニューの項目が見えなかった (実測)

### 定型文のドラッグ＆ドロップ: 小窓の中だけで扱う

- OLE のドラッグ＆ドロップ (`DoDragDrop`) は使わず、一覧 (`DragListBox`) がマウスを捕捉して動きを追う。
  他のアプリへの受け渡しは無い。ドラッグ中はマウスの動きを ListBox 本来の処理に渡さない (選択が動くため)
- 入れ替え・グループに入れる計算は `PhraseMoves` (純粋関数) にまとめ、単体テストしている。
  グループが自分の中に入って入れ子が輪になる動きは、できないようにしている
- ドラッグ中に別の階層を開いても、元の枠 (どのグループの何番か) を覚えているので、別の階層へ移せる
- 見出しの階層名 (`BreadcrumbLabel`) は、名前ごとの位置が分かるように自分で描いている
- 右クリックのメニューを出したまま (小窓が前面のまま) ホットキーを離したときは、小窓を隠す前に
  元のアプリへ前面を戻す。前面のまま隠すと Windows が別のアプリを前面にしてしまうため (実測)。
  ダイアログの持ち主も、元のアプリへの切り替えが終わってから隠す (タイマーで最大 3 秒待つ)

### 小窓: フォーカスを奪わない最前面ウインドウ

| 目的 | 実装 |
|---|---|
| 表示してもアクティブにしない | `ShowWithoutActivation` を true、拡張スタイルに `WS_EX_NOACTIVATE` |
| クリックされてもアクティブにしない | `WM_MOUSEACTIVATE` に `MA_NOACTIVATE` を返す (クリック自体は一覧に届く) |
| タスクバーと Alt+Tab に出さない | `WS_EX_TOOLWINDOW` |
| 最前面 | `WS_EX_TOPMOST` をスタイルで指定し、表示のたびに `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)`。WinForms の `TopMost` プロパティは表示時にアクティブになることがあるため使わない |
| 表示位置 | カーソルの右下。右端・下端では反対側に回り込み、カーソルのあるモニターの作業領域に収める (マイナス座標のモニターも可) |
| 大きさ | 幅は固定、高さは見出しと件数に合わせる (モードを切り替えて行数が変わったら、位置も決め直す)。一度に見せるのは 15 行までで、それ以上はスクロール |
| 見た目 | DWM の `DWMWA_WINDOW_CORNER_PREFERENCE` で角丸。Windows 11 では DWM が枠線と影も付けるので、白い背景の上でも輪郭が見える |
| 初回表示の速さ | 起動時に小窓と一覧のウインドウを作っておき、表示・非表示を切り替えるだけにする |

`&` が消えないよう、一覧の描画は `TextFormatFlags.NoPrefix` を付けている。

## 開発上の制約

`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` は `/langversion` に C# 5 までしか
受け付けない。**ソースは C# 5 互換**で書くこと。文字列補間、自動プロパティ初期化子、
式形式メンバー、`nameof`、`?.`、`out var` は使用不可。

ソースは BOM なし UTF-8。csc は既定だと ANSI (Shift-JIS) として読むので、`build.ps1` で
`/codepage:65001` を指定している。

PowerShell スクリプトは **BOM 付き UTF-8** で保存すること。
Windows PowerShell 5.1 は BOM の無い UTF-8 を ANSI として読むため日本語が壊れる。

## 検証

```powershell
# 全部 (純粋関数 → 設定 → 履歴 → クリップボード読み取り → exe を起動しての E2E)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\verify.ps1

# E2E のうち、履歴モードだけ / 定型文モードだけを流す (検証 1〜5 はどちらでも流す)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\verify.ps1 -E2E History
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\verify.ps1 -E2E Phrases

# E2E を省略 (マウスとキーボードを使わない。設定画面のキーの取り込みの検証で、設定画面が一瞬出る)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\verify.ps1 -SkipE2E

# E2E で表示中の小窓を撮影 (見た目の確認用)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\verify.ps1 -ScreenshotPath $env:TEMP\copipe.png
```

`verify.ps1` は .NET Framework 4.8 のアセンブリを読むため **Windows PowerShell 5.1** で実行する。

実行すると次のことが起きる。

- **クリップボードを書き換える** (元がテキストなら最後に戻す。画像などは戻せない)。
  途中で失敗しても Ctrl+C で止めても戻す
- **設定・履歴・定型文のファイルを書き換える** (始める前に退避し、最後に元へ戻す。
  検証でコピーした目印が利用者の履歴に混ざらない)
- **検証を途中で止めた (ウインドウを閉じた・強制終了した) ときは、上の「元へ戻す」が動かない**。
  退避したときに「まだ戻していない」印を書いておくので、次のどちらかで元に戻る
  - 次に検証を流すと、始めに自動で戻してから検証する
  - すぐ戻すなら `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\Restore-CopipeData.ps1`
    (Copipe を止めて戻し、起動していたなら起動し直す。止まった検証が続いたときは一番古い退避から戻す)
- 起動中の Copipe を、クリップボードを使う検証の前に終了する (小窓に WM_CLOSE を送る正常終了。
  応答しなければ強制終了)。起動したままだと、検証がクリップボードに置く文字を履歴に拾ってしまうため。
  **検証の前に起動していたなら、最後に起動し直す**
- ダブルクリックでの入力を確かめるため、入力先のテキストボックスの画面を一時的に出す
- クリップボードを開いたままにする等の細工をする補助の powershell.exe を、裏で一時的に起動する
- E2E では**マウスカーソルを動かし、ホットキーを擬似入力し、表示中の小窓の中央を 1 回左クリックする**
  (クリックしてもフォーカスを奪わないことの確認。クリック位置に小窓があることを確かめてから押す)。
  カーソル位置は最後に戻す。実行中はマウスとキーボードに触らないこと
- 定型文の E2E では、小窓の行を**右クリック**してメニューを選び、出てきたダイアログの入力欄に文字を書き込んで
  OK・キャンセルを押す。削除の確認にも答える。定型文は検証用の中身に差し替え、最後に元へ戻す
- E2E で使うホットキーは、**登録できて、かつ擬似入力が実際に届くもの**を選ぶ (既定の F1 から順に試す)。
  別のアプリが横取りしているキーを使うと、アプリの不具合と見分けがつかないため

tools/verify.ps1                 検証ハーネス

  interop/NativeMethods.cs       Win32 API の宣言
  model/ClipboardSnapshot.cs     読み取った内容 (種類とテキスト / ファイル一覧)
  model/PhraseNode.cs            定型文モードの枠の中身 (定型文か、10 個の枠を持つグループ)

  services/
    ClipboardReader.cs           Win32 API でクリップボードを読む
    ClipboardWriter.cs           Win32 API でクリップボードに書く (持ち主で自分の書き込みを見分ける)
    TextInserter.cs              クリップボードに置いて Ctrl+V を送り、テキストカーソルの位置に入力する (順番待ちあり)
    PopupKeys.cs                 小窓を出している間だけ、数字キー・モードキー・Esc を登録して受け取る
    PhraseBook.cs                定型文の読み書き (phrases.json。手書きの過不足も直して読む)
    ClipboardMonitor.cs          クリップボードの変化の通知 (WM_CLIPBOARDUPDATE) を受ける
    ClipboardHistory.cs          履歴 (新しい順・重複は先頭へ・10 件まで・JSON 保存)
    HoldHotkey.cs                「押し続けている間」を Pressed / Released で知らせる
    DoubleTapWatcher.cs          修飾キーのダブルタップを Raw Input で見張る (読むだけ)
    MouseClickWatcher.cs         マウスのボタンを押した瞬間を Raw Input で受け取る (出したままの小窓の外のクリック)
    DoubleTapTracker.cs          ダブルタップの判定 (純粋な状態機械)
    Settings.cs                  設定ファイルの読み書き (%LOCALAPPDATA%\Copipe\settings.ini)
  ui/

    PopupRow.cs                  小窓の一覧の 1 行 (項目・グループ・空き)
    RowMenu.cs                   定型文の行の右クリックメニュー (Windows 標準のポップアップメニュー)
    PhraseDialog.cs              定型文の登録・編集、グループの作成・名前の変更のダイアログ
    DialogOwner.cs               ダイアログの持ち主にする見えないウインドウ (閉じた後に元のアプリへ前面を戻すため)
    DragListBox.cs               行をドラッグできる ListBox (小窓の中だけのドラッグ)
    DropTarget.cs                ドラッグした項目を落とす先 (入れ替え・グループに入れる・階層に出す)
    BreadcrumbLabel.cs           見出しの階層名 (定型文 > 社外 > …)。落とす先にもなる
    PopupPlacement.cs            表示位置の計算 (純粋関数)
    PreviewText.cs               一覧の 1 行の文字列 (純粋関数)
    AppIcon.cs                   埋め込んだ copipe.ico から、トレイの大きさのアイコンを読む
    SettingsDialog.cs            設定画面 (ホットキー・ダブルタップ・モードキーの取り込み、貼り付けの操作)
    HotkeyText.cs                キーの表示名・保存形式・使えるキーかの判定 (純粋関数)
